# HiveBooks: встановлення та оновлення

Сайт працює лише українською. Платформа BeeOne завантажується автоматично
з https://github.com/OlexandrDevelop/beeone (гілка `beeone-16`).

## Встановлення однією командою

Потрібні Docker і Docker Compose v2. У каталозі репозиторію:

```bash
./install.sh
```

Скрипт спитає:

1. **базу даних**: MariaDB (типово) або PostgreSQL;
2. **ім'я сайту** (домен; для перевірки на цьому комп'ютері — `localhost`);
3. **пароль адміністратора** (двічі; порожній — буде створено випадковий і показано один раз).

Далі він сам збере образ, запустить сервіси й створить порожній сайт без демоданих.
Відкрийте http://localhost:8080, користувач **Administrator**. Перший вхід показує вибір:
**«Заповнити демоданими»** або **«Ввести початкові налаштування організації»** (короткий
майстер). Демодані можна додати пізніше в «Початкові налаштування» (меню користувача).

Без запитань (скрипти, CI):

```bash
./install.sh --db postgres --site erp.example.com --admin-password 'ВашПароль' --http-port 8080 --yes
```

Параметри: `--db mariadb|postgres`, `--site`, `--admin-password`, `--http-port`,
`--project` (назва проєкту Compose, якщо на машині кілька встановлень), `--yes`.

## Вибір бази даних

| | MariaDB | PostgreSQL |
|---|---|---|
| Compose-файл | `docker-compose.yml` | `docker-compose.postgres.yml` |
| Том даних | `db-data` | `pg-data` |
| Стан | повністю підтримується | повністю підтримується: встановлення, проведення документів і демодані |

Тип бази обирається **один раз** при встановленні й не змінюється. `install.sh`
записує вибір у файл `.env` (`COMPOSE_FILE`), тому звичайні `docker compose ps|logs|down`
працюють без додаткових параметрів.

## Оновлення

```bash
git pull
./install.sh
```

Скрипт бачить `.env`, нічого не питає, перебудовує образ і запускає сервіс `init`,
який виконує міграції. Дані та пароль не змінюються. Перед оновленням зробіть резервну копію.
Для фіксації релізу задайте `BEEONE_REF` у `.env` як незмінний Git tag платформи.

## Easypanel

1. Створіть **Compose service**, джерело — цей GitHub-репозиторій, **Build Path — `/`**.
2. Docker Compose File — `docker-compose.yml` (MariaDB) або `docker-compose.postgres.yml` (PostgreSQL).
3. В Environment задайте `SITE_NAME` (домен без https://), `DB_ROOT_PASSWORD`, `ADMIN_PASSWORD`;
   увімкніть **Create .env file**. `LOAD_DEMO` не потрібна (типово `0`: демодані не додаються).
4. Додайте домен → сервіс `frontend`, HTTP-порт **8080**. HTTPS завершує Easypanel.
   Файл `compose.ports.yaml` потрібен лише для локального встановлення.
5. Deploy. Вхід: **Administrator**, пароль із `ADMIN_PASSWORD`.

Для приватного репозиторію додайте SSH-ключ сервісу Easypanel як read-only deploy key у GitHub.

## Дані та безпека

- База, файли сайту та черга зберігаються в томах Docker. **Не виконуйте `docker compose down -v` на робочому сайті**: це видаляє всі дані.
- Зміна `ADMIN_PASSWORD` після створення сайту не змінює пароль існуючого користувача: змінюйте його в інтерфейсі.
- Якщо `init` завершився помилкою, застосунок не відкривається: `docker compose logs init`.
- `LOAD_DEMO=1` додає демодані під час першого запуску, але лише на сайті без власних даних.
- Зміна коду конфігурації вимагає нового build (`./install.sh`); звичайний restart не оновлює код.

## Якщо потрібна збірка з локальної копії платформи

`./install.sh --beeone-context /шлях/до/клону/beeone` з `BEEONE_REF=<гілка цього клону>` у `.env`.
Типова збірка з GitHub від цього не змінюється.
