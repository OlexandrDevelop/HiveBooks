# BeeOne — автоматичне деморозгортання

Цей репозиторій містить одну конфігурацію. Dockerfile автоматично завантажує
платформу з https://github.com/OlexandrDevelop/beeone (гілка `beeone-16`).
ERPNext і друга конфігурація не встановлюються.

## Easypanel

1. Створіть **Compose service**, джерело — цей GitHub-репозиторій,
   Compose-файл — `docker-compose.yml`, **Build Path — `/`**.
2. В Environment задайте `SITE_NAME` (домен без https://), `DB_ROOT_PASSWORD`
   та `ADMIN_PASSWORD` (власні довгі паролі); увімкніть **Create .env file**. `LOAD_DEMO=1` увімкнено за замовчуванням.
3. Додайте домен → сервіс `frontend`, HTTP-порт **8080**. HTTPS завершує Easypanel.
4. Deploy. Перша збірка завантажує BeeOne та збирає JS/CSS; сервіс `init`
   створює сайт, встановлює конфігурацію, мігрує базу та наповнює демоданими.
   Вхід: **Administrator**, пароль із `ADMIN_PASSWORD`.

Для приватного репозиторію додайте SSH-ключ сервісу Easypanel як read-only deploy key у GitHub. Платформа BeeOne має
бути доступна build-середовищу: типовий URL публічний; токени не вставляйте в URL
чи build args. Якщо платформа приватна, потрібен окремо налаштований BuildKit
secret/SSH або доступний образ; пароль від GitHub конфігурації не успадковується.

Достатньо змінних й одного GitHub URL; ручні bench-команди не потрібні.
Для локального запуску: `cp .env.example .env`, заповніть паролі,
`docker compose up --build -d`. Опублікованих host-портів немає: для локального
доступу додайте override із `frontend.ports: ["127.0.0.1:8080:8080"]`.

## Дані й оновлення

MariaDB, файли сайту та черга зберігаються в окремих volumes. Повторний Deploy
виконує міграції, але завершений demo seed не повторюється й дані не скидаються.
`LOAD_DEMO=0` пропускає наповнення. Зміна `ADMIN_PASSWORD` після створення сайту
не змінює пароль існуючого користувача; змінюйте його через інтерфейс.
При помилці init застосунок не відкривається: перегляньте logs сервісу `init`.
Незавершений accounting seed потребує перевірки, автоматичного видалення немає.
Перед оновленням зробіть backup. **Не виконуйте `down -v` для робочого сайту.**
Для фіксації релізу задайте `BEEONE_REF` як незмінний Git tag, наявний у платформі.
Зміна коду конфігурації вимагає нового build; звичайний restart не оновлює код.

Бухгалтерія: невелика торгова компанія з документами за останній місяць.
Торгівля: стартові довідники (організація, склад, товари, покупець,
постачальник і тип ціни); проведених операцій у цьому seed немає.
